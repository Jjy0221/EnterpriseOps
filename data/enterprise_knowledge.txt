EnterpriseOps Copilot 企业知识库测试文档

【1. API 套餐与调用额度】
企业开放平台提供基础版、专业版和企业版三种套餐。基础版每月包含 10000 次 API 调用额度，适合个人开发者和小规模测试。专业版每月包含 80000 次 API 调用额度，支持更高并发和更完整的监控能力。企业版不设置固定统一额度，通常根据合同约定的并发量、调用量和 SLA 单独配置。套餐额度按自然月统计，未使用的调用次数不会自动结转到下个月。

【2. API 超额与限流规则】
当基础版或专业版用户达到当月调用额度后，新的 API 请求会被限流。系统通常返回配额不足相关错误，不会继续无上限放行。用户可以升级套餐或联系管理员申请临时扩容。单个账号如果在短时间内出现异常突发流量，即使月度额度尚未耗尽，也可能触发每秒请求数限制。限流属于平台保护机制，不代表账号被封禁。

【3. 密码错误与账号锁定】
员工登录企业系统时，如果连续输错密码 5 次，账号会被临时锁定 30 分钟。锁定期间即使输入正确密码也不能立即登录。若员工确认不是本人操作，应尽快联系服务台检查异常登录记录。管理员可以在身份管理后台提前解除锁定，但解除前需要完成员工身份确认。单纯忘记密码时，应优先使用“忘记密码”流程重置密码。

【4. 密码重置要求】
密码重置后，新密码长度不得少于 12 位，并且至少包含大写字母、小写字母、数字和特殊字符中的三类。新密码不能与最近 5 次使用过的密码相同。密码重置成功后，旧密码立即失效。对于绑定了多因素认证的账号，重置密码不会自动移除 MFA 设备，用户仍需通过原有的第二验证因子完成登录。

【5. VPN 常见故障排查】
员工反馈 VPN 无法连接时，服务台应先确认客户端版本是否为公司当前支持版本，再检查本地网络是否正常。如果客户端版本过旧，应先升级客户端后重试。若用户能正常访问互联网但 VPN 仍提示认证失败，需要进一步检查账号状态和 MFA。若大量员工在同一时间无法连接，则应优先判断是否为 VPN 网关或网络出口故障，而不是逐个重装客户端。

【6. VPN 客户端版本要求】
公司目前要求 Windows 终端使用 5.3 及以上版本的 VPN 客户端，macOS 终端使用 5.2 及以上版本。低于最低版本的客户端可能因安全策略不兼容而被拒绝连接。升级前建议先退出正在运行的 VPN 会话。升级安装完成后通常不需要重新导入企业配置，但如果配置文件损坏，可从 IT 门户重新下载标准配置。

【7. 软件安装申请】
员工如需安装未在软件中心提供的第三方软件，需要提交软件安装申请。申请内容至少包括软件名称、版本、用途和使用期限。涉及付费软件时还要说明预算归属。普通办公软件由直属主管审批，涉及开发工具、网络扫描工具或高权限组件的软件还需要信息安全团队复核。未经审批不得自行安装来源不明的软件。

【8. 工单优先级定义】
工单分为 P1、P2、P3、P4 四个优先级。P1 表示核心业务完全中断且没有可行替代方案，例如全公司统一登录服务不可用。P2 表示重要业务严重受影响，但仍存在部分替代方式。P3 表示单个用户或小范围功能异常，对核心业务影响有限。P4 主要用于咨询、权限申请和一般服务请求。优先级越高，要求的响应时间越短。

【9. 工单响应时限】
P1 工单要求 15 分钟内首次响应，并持续跟进直到恢复。P2 工单要求 30 分钟内首次响应。P3 工单要求 4 个工作小时内首次响应。P4 工单要求 1 个工作日内首次响应。首次响应不等于问题必须已经解决，而是服务台需要确认已受理，并向用户说明当前处理状态和下一步动作。

【10. 工单关闭规则】
技术人员解决问题后，工单应记录处理过程、根因和最终解决方案。对于需要用户确认的工单，用户确认恢复后可以关闭。如果用户连续 3 个工作日没有回复，服务台可以发送一次提醒；提醒后仍无反馈，可按“用户未响应”关闭。P1 和重大故障类工单不能只写“已解决”，必须补充根因分析和预防措施。

【11. 数据库访问申请】
生产数据库默认不向普通员工开放直接访问权限。开发人员如需查询生产数据，必须提交数据库访问申请，并说明业务原因、数据库名称、所需权限和有效期。只读权限应优先于读写权限。涉及敏感字段的数据访问还需要数据负责人审批。临时权限到期后应自动回收，不建议使用长期永久授权。

【12. 生产变更审批】
生产环境变更需要提交变更单，内容包括变更目标、影响范围、执行步骤、验证方法和回滚方案。普通低风险变更至少需要团队负责人审批。涉及数据库结构、网络策略或核心服务重启的变更，需要相关系统负责人共同审批。紧急变更可以先处理故障，但必须在事后补充变更记录和复盘说明。

【13. 文件共享与敏感信息】
包含客户身份证号、银行卡号、合同扫描件或其他敏感信息的文件，不得通过个人网盘或公共匿名链接共享。内部共享应使用公司批准的企业网盘，并根据最小权限原则设置访问范围。对外共享前应确认业务必要性和接收方身份。超过业务期限后，应及时取消共享权限或删除临时共享链接。

【14. 离职账号处理】
员工离职当天，人力资源系统会触发账号停用流程。企业邮箱、VPN、代码仓库和内部管理系统权限应在离职生效时间后关闭。业务负责人需要提前确认重要文件、项目权限和共享资源是否已经完成交接。对于特殊岗位，如财务管理员或系统管理员，还需要额外检查高权限账号、密钥和服务账号是否完成移交或轮换。

【15. MFA 多因素认证】
公司关键系统默认要求开启多因素认证。支持的第二验证因子包括身份验证器动态验证码和已登记的安全设备。员工更换手机前，应先在身份管理门户绑定新的验证设备。如果原手机丢失且无法使用，应联系服务台进行身份核验后重置 MFA。服务台不得仅凭聊天消息直接解除多因素认证。

【16. 邮件钓鱼处理】
员工收到可疑邮件时，不应点击其中的链接或打开未知附件。应通过邮件客户端的“报告钓鱼”功能提交安全团队分析。如果已经点击链接但没有输入账号密码，也应及时上报。如果已经输入企业账号密码，应立即修改密码并通知安全团队检查登录记录。对明显伪造的内部付款或转账邮件，应通过其他渠道向相关人员二次确认。

【17. 服务器磁盘告警】
当服务器磁盘使用率达到 80% 时触发预警，达到 90% 时触发高优先级告警。处理时应先确认增长最快的目录和文件类型，再判断是日志堆积、缓存文件、临时文件还是业务数据增长。未经确认不应直接删除生产数据。对于持续增长的日志，应同时检查日志轮转和保留策略是否正常。

【18. 日志保留策略】
普通应用日志默认在线保留 30 天，安全审计日志至少保留 180 天。涉及监管或合同要求的系统，可以根据要求延长保留时间。日志中不应记录明文密码、完整银行卡号等高敏感信息。开发人员排查问题时如果需要临时提高日志级别，应在问题处理完成后恢复默认级别，避免长期产生大量调试日志。

【19. 远程办公设备要求】
远程办公优先使用公司统一管理的终端设备。公司终端需要启用磁盘加密、终端防护和自动补丁更新。未经批准，不建议在个人电脑上保存企业敏感文件。远程访问内部系统时应使用公司 VPN，并遵守 MFA 要求。发现设备遗失时，应立即联系服务台和直属主管，以便启动远程锁定或数据保护措施。

【20. 重大故障沟通机制】
重大故障发生后，应尽快建立统一沟通群，并由指定负责人持续发布状态。对内更新应包含当前影响范围、已采取措施、下一次更新时间和待确认风险。技术团队在故障处理中应避免多人同时对生产环境执行未经协调的修改。故障恢复后需要进行复盘，形成时间线、根因、影响评估和后续改进项。
